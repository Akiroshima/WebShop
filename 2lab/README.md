# Муркет — демо-приложение интернет-магазина

Демо-приложение интернет-магазина: frontend-only Angular с браузерным мок-слоем вместо бэкенда (мок-БД в `localStorage`, детерминированное заполнение тестовыми данными, эмуляция задержек и HTTP-ошибок). Реализованы все функциональные слои — доменные мок-обработчики, core-сервисы, каталог товаров, поиск и фильтрация, корзина, оформление заказов, личный кабинет покупателя, восстановление аккаунта, валидаторы и уведомления. Вход под демо-учётными записями описан ниже.

> Магазин зоотоваров «Муркет» — «всё для счастливого кота». Реализация лабораторной работы №2 по спецификации из `1lab/shop-specification.md` (клиентская часть; серверные эндпоинты `/api/v1/...` эмулируются мок-слоем в браузере).

## Стек

- Angular 20+, standalone-компоненты, TypeScript strict
- SCSS, единственный брейкпоинт проекта — **768px** (граница мобильной вёрстки)
- PrimeNG 20+ с темой Aura (`@primeuix/themes`, кастомный пресет «Муркет», только светлый режим) и PrimeIcons
- Русская локаль: `LOCALE_ID = ru`, `registerLocaleData(localeRu)`, русские переводы встроенных текстов PrimeNG (`core/config/primeng-ru.ts`)
- Тесты: Karma + Jasmine (ChromeHeadless)

## Установка и запуск

Требуется Node.js LTS (20.19+ или 22.12+) и npm; для запуска unit-тестов в ChromeHeadless должен быть установлен Google Chrome (при его отсутствии автоматически используется Microsoft Edge).

```bash
npm install
npm start
```

После запуска приложение открывается по адресу [**http://localhost:4200**](http://localhost:4200). Гость попадает на экран входа; после авторизации пользователь переходит на домашний экран магазина.

Прочие команды:

```bash
npm test           # unit-тесты (Karma + Jasmine, ChromeHeadless)
npm run build      # production-сборка (ng build --configuration production)
npm run watch      # пересборка разработки при изменениях
```

## Демо-учётные записи и сброс данных

Данные приложения хранятся в браузере в мок-БД (`localStorage`, ключ `mock.db.v1`) и инициализируются детерминированным набором тестовых данных.

### Демо-учётные записи

| **Логин**  | **Пароль**  | **Роль**      | **Возможности**                                                              |
| ---------- | ----------- | ------------- | ---------------------------------------------------------------------------- |
| `customer` | customer123 | покупатель    | Просмотр каталога, управление корзиной, оформление заказов, просмотр профиля |
| `admin`    | admin123    | администратор | Управление товарами, просмотр заказов и пользователей                        |

Войти можно также по email (`anna.smirnova@example.com`) или телефону (`+7 999 123-45-67`) демо-покупателя.

### Тестовые данные

В исходный набор данных входят:

- Каталог товаров с категориями, ценами, описаниями и изображениями (41 товар, 5 категорий, 6 брендов; есть товары «нет в наличии» и неактивные).
- Тестовые пользовательские аккаунты с разными ролями.
- Корзина покупателя и демонстрационные заказы со статусами «Новый», «Подтверждён», «Доставлен».
- Данные для проверки авторизации и восстановления аккаунта.
- Тестовые сценарии для проверки валидации форм, уведомлений, задержек и HTTP-ошибок.

### Промокоды для проверки

| **Код**     | **Скидка**   | **Условие**                  | Что проверяет                                |
| ----------- | ------------ | ---------------------------- | -------------------------------------------- |
| `МУР10`     | 10 %         | сумма от 1 000 ₽             | процентная скидка                            |
| `СКИДКА500` | 500 ₽        | сумма от 3 500 ₽             | фиксированная скидка                         |
| `ПРОМО`     | 15 %         | срок действия истёк          | ошибку «Промокод не найден или не действует» |
| `ЛИМИТ`     | 5 %          | лимит использований исчерпан | ошибку «Промокод не найден или не действует» |
| `СБОЙ500`   | —            | —                            | имитацию 500-й ошибки сервера                |

### Тест-триггеры задержек и ошибок

- Логин, содержащий слово `медленно`, отвечает с дополнительной задержкой +2 с.
- Логин, содержащий слово `сбой`, имитирует 500-ю ошибку сервера.
- Промокод `СБОЙ500` при применении имитирует 500-ю ошибку сервера.
- Пять неудачных попыток входа подряд → 429 «Слишком много попыток входа. Попробуйте через минуту».

### Сброс данных

Чтобы вернуть приложение к исходному состоянию, например после изменения товаров или оформления тестовых заказов:

1. Откройте DevTools (`F12`) → **Application** → **Local Storage** → `http://localhost:4200`.
2. Удалите ключ `mock.db.v1`, содержащий данные мок-БД. Для полной очистки также удалите ключ сессии `mock.session.userId` и данные временного потока восстановления (`mock.recovery.v1` в `sessionStorage`), если они используются приложением.
3. Обновите страницу (`F5`). При отсутствии или повреждении данных приложение должно повторно инициализировать исходный набор тестовых данных.

Для полной очистки хранилищ можно выполнить в консоли DevTools:

```javascript
localStorage.clear();
sessionStorage.clear();
```

## Особенности демо-режима

- Каждый мок-запрос задерживается примерно на 500–800 мс, имитируя ответ сервера.
- Реальный бэкенд отсутствует: товары, пользователи, корзина и заказы обрабатываются браузерным мок-слоем, который подменяет `HttpBackend`, — приложение работает через обычный `HttpClient` и REST-пути `/api/v1/...`.
- Данные сохраняются в `localStorage` и остаются доступными после перезагрузки страницы.
- Восстановление доступа работает в демонстрационном режиме: код восстановления выводится в консоль браузера (F12 → Console), письма и SMS не отправляются.
- Тёмная тема отключена (`darkModeSelector: false`); используется только светлая цветовая схема.

## Структура каталогов

Внутри `src/app` код располагается в пяти ветках: `core`, `mock`, `shared`, `layout` и `features`.

```text
src/app/
├── core/          — сервисы и конфигурация
│   ├── config/
│   │   ├── app.config.ts
│   │   ├── app.routes.ts
│   │   ├── primeng-ru.ts
│   │   └── theme.ts
│   └── services/  — auth, catalog, cart, orders, profile, admin, notifications
├── mock/          — мок-БД, обработчики запросов и тестовые данные
│   ├── db/        — mock-db (localStorage), seed, логика промокодов
│   ├── handlers/  — auth, catalog, cart, orders, profile, admin
│   └── mock-backend.ts
├── shared/        — модели, валидаторы, пайпы и общие компоненты
├── layout/        — оболочка приложения, навигация и страницы 403/404
└── features/      — функциональные модули интернет-магазина
    ├── auth/      — вход и восстановление аккаунта
    ├── catalog/   — каталог, поиск и фильтрация товаров
    ├── cart/      — корзина покупателя
    ├── orders/    — оформление заказов и история покупок
    ├── profile/   — личный кабинет
    └── admin/     — управление товарами, заказами и пользователями

src/styles.scss    — глобальные стили
src/styles/        — SCSS-примеси и адаптивная вёрстка
src/assets/        — SVG-иллюстрации товаров
```

`src/main.ts`, `src/index.html` и `src/styles.scss` — стандартные точки входа Angular CLI вне `src/app`.
