# БД «Муркета» — PostgreSQL 16

Схема данных в **третьей нормальной форме (3НФ)** и демо-данные. Скрипты
применяются `psql` в порядке номеров; скобка — под кем запускать.

| Скрипт | Запуск | Что делает |
| --- | --- | --- |
| `01_database.sql` | `postgres` (суперпользователь) | Роль `murket` (право `CREATEDB` — нужно тестам) и база `murket`; идемпотентен через `\gexec` |
| `02_schema.sql` | `murket` | 13 таблиц, sequence номеров заказов, внешние ключи, CHECK-ограничения, индексы |
| `03_seed_demo.sql` | `murket` | Демо-данные (2 учётки, каталог 41 товар, промокоды, корзина, заказы №1001–1003); идемпотентен (`ON CONFLICT DO NOTHING`) |

```bash
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -f 01_database.sql
psql -h 127.0.0.1 -p 5432 -U murket -d murket -f 02_schema.sql
psql -h 127.0.0.1 -p 5432 -U murket -d murket -f 03_seed_demo.sql
```

Приложение схему **не создаёт** (ни EF-миграций, ни `EnsureCreated`):
единственный источник — `02_schema.sql`. Сид приложения идемпотентен и
пропускается, если пользователи уже есть, поэтому база, наполненная
`03_seed_demo.sql`, при старте не меняется. Демо-пароли: `customer` /
`customer123`, `admin` / `admin123` (в Production действует SEC-001, см.
README бэкенда).

Строка подключения по умолчанию (Development):

```
Host=127.0.0.1;Port=5432;Database=murket;Username=murket;Password=murket
```

В Production обязательна переменная `Database__ConnectionString` со
собственными значениями.

## Состав схемы

| Таблица | Назначение |
| --- | --- |
| `users` | учётные записи: логин/email/телефон уникальны (регистронезависимые индексы по `lower(...)`, телефон — E.164), пароль — PBKDF2 |
| `categories`, `brands` | справочники каталога |
| `products` | товары: цена/остаток только здесь, артикул уникален (`upper(sku)`) |
| `promos` | промокоды: тип `percent`/`fixed`, период, лимит использований |
| `addresses` | адреса доставки пользователей |
| `carts`, `cart_items` | корзина на пользователя; только ссылки на товары и количества |
| `orders`, `order_items` | заказы: снимки состава/адреса на момент оформления |
| `refresh_tokens` | refresh-токены (хранится только SHA-256-хэш) |
| `recovery_codes` | коды восстановления доступа (хэш, TTL 10 минут, счётчик попыток) |
| `password_reset_tokens` | токены сброса пароля (хэш — первичный ключ, TTL 15 минут) |

Номера заказов выдаёт `sequence order_number_seq` (старт 1001; после
демо-заказов №1001–1003 сид сдвигает счётчик — следующий номер 1004).

## Почему 3НФ

Требование 3НФ: каждая неключевая колонка зависит только от ключа своей
таблицы (нет транзитивных зависимостей), все неключевые атрибуты
неключевым образом ни от чего не зависят.

- **Цены и остатки — только в `products`.** `cart_items` хранит лишь
  `product_id` и `quantity`: цена подтягивается из `products` при каждом
  чтении, поэтому изменение цены одномоментно видно всем корзинам и не
  может «разъехаться». Нарушение 2НФ-типа (дублирование цены в корзине)
  отсутствует по построению.
- **Счётчики товаров не хранятся.** Количество товаров категории/бренда
  вычисляется (`COUNT` по активным товарам) — нет избыточной колонки,
  которая могла бы рассинхронизироваться (классическая транзитивная
  зависимость `category → product_count`, устранена вычислением).
- **Справочники отделены.** Название категории/бренда не повторяется в
  товарах — только `category_id`/`brand_id` (FK); уникальность имён
  держат сами справочники.
- **Уникальность контактов — индексы, а не прикладная логика:**
  `lower(login)`, `lower(email)`, `phone` (partial — только непустые).
- **Снимки заказа — исторические факты, а не дублирование.** `orders`
  хранит получателя, адрес, промокод и итоги, `order_items` — название,
  артикул и цену **на момент оформления**. Это не нарушение 3НФ: снимок
  зависит только от ключа заказа и по смыслу неизменяем (что было куплено
  и по какой цене); изменение каталога задним числом заказ не меняет
  (проверяется зоной B-23).
- **Корзина применяет промокод ссылкой** `carts.promo_id` → `promos.id`
  (`ON DELETE SET NULL`): код не дублируется.
- **Адрес «по умолчанию» единственный** на пользователя — partial unique
  index `addresses_one_default`.
- Целостность адресатов каскадов: удаление пользователя сносит его
  адреса/корзину/токены (`CASCADE`); удаление товара очищает корзины
  (`CASCADE`), но заказы хранит (`order_items.product_id SET NULL` —
  снимок остаётся); категории защищены (`RESTRICT` — категорию с товарами
  удалить нельзя).

ER-диаграмма — в [README](../../README.md) 4-й лабораторной.

## Тестовые базы

Интеграционные тесты и зоны B-01…B-23 создают изолированные базы
`murket_t_<pid>_…` клонированием шаблона (поэтому роли `murket` требуется
`CREATEDB`). Базы удаляются после прогона; строка подключения тестов —
`MurketTests__ConnectionString` (умолчание совпадает с dev-строкой выше).
